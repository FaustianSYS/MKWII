# Software Verification Plan (SVP)

## 1. Verification Methods

| DAL | Requirements-based test | Coverage | Static analysis | Review |
|-----|------------------------|----------|-----------------|--------|
| A | Required | 100% statement; MC/DC on tagged logic | Required | Required |
| B | Required | 100% statement | Required | Required |

## 2. Test Levels

- **Unit tests** — `tests/unit/` per module
- **Integration tests** — `tests/integration/` end-to-end scenarios
- **Robustness tests** — fault injection (invalid inputs, saturation)

## 3. Coverage

Build with `safety-verify` preset (`FLIGHTSIM_ENABLE_COVERAGE=ON`). Generate report via `cmake --build build/safety-verify --target coverage`.

## 4. Static Analysis

- `clang-tidy` with project config in `tools/static_analysis/`
- `cppcheck` with MISRA-oriented rules

## 5. Traceability

RTM generated by `tools/trace_gen/trace_gen.py` from `@req` tags in source.

## 6. MC/DC

Functions tagged `@mcdc` in safety-critical decision logic require MC/DC analysis per DAL A objectives.
